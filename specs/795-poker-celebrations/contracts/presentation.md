# Presentation contract

Live selection consumes authoritative state; it never returns or mutates gameplay. Only a newly observed same-hand SETTLED transition with valid settlement identity and newer version may start an effect; remaining Winner time does not gate it. A started effect runs 1600 ms of hero art plus a 400 ms ring exit. Normal hand/reveal/turn/action/snapshot changes cannot cancel it; resumed gameplay immediately dims the effect. Consumed events cannot replay after preference changes, resync or reconnect. A verified winning Straight, Flush, Full House, Four of a Kind, Straight Flush or Royal Flush takes precedence over Monster Pot, which takes precedence over Win Streak. Existing viewer-first confirmed-winner traversal is preserved.

Hand selection passes exactly the evaluator's best five normalized cards and category title for a confirmed positive main/side recipient. The viewer's two current cards or both publicly revealed opponent cards may prove the hand. Without both hole cards, only a public-board Royal Flush proves the exact best five; every other unverified board-only result is skipped. Live rendering rejects an invalid/missing title or five-card set. Labeled `demo: true` calls may pass synthetic legal cards. All six hand categories use the Royal Flush card nodes, style, sizes and duration; only the title and faces vary. Monster Pot selection carries the identified winner's confirmed main/side recipient awards summed across pots, excluding return pots; its caption is `WIN {amount} CH`. Both visual sizes receive the same selection data.

The local Win Streak consumes valid, distinct newly observed settlements. Positive main/side awards are wins, split recipients each count, eligible non-winners and folded seats lose, sit-outs have no result, and a return-only result is not a win. It displays each user's actual count from ×5 onward, including after a higher-priority effect. Streak state is discarded on reconnect/resync, refresh/rejoin, identity/seat/table change, initial replay or uncertain sequence; there is no persisted or remote history.

Preview controls are constructed only for consistent deploy-preview metadata. Their callback calls a private UI presentation function with `demo: true`; no state fabrication, command, transport, payouts, live dedupe or streak mutation. Synthetic amount and selectable ×5/×6/×7/×8/×12 counts carry an explicit DEMO label. Actionable and modal layers remain readable above the FX. Natural exit removes all claim-bearing elements only when its 400 ms decorative tail begins.

Compact presentation captures the selected winner's `userId + seatNo` at start and resolves that exact identity through every existing render/layout update, including while only the decorative tail remains. A different/missing seat owner clears immediately. With identity intact, invalid measurements, viewport limits or summary collisions trigger a short overlay-only fade; cleanup uses the existing timer and cannot extend the original hero-plus-exit deadline. Failure to find a safe initial position skips the effect. The large presentation is not affected.

In the deploy-preview panel, compact mode has one native selector listing the currently visible nonlocal seats, including bots. All six hand demos, Monster Pot and Win Streak resolve the exact selected `userId + seatNo` again on activation. If it is no longer visible or selected, the preview does nothing and prompts for a valid target; it never substitutes the first available seat. The large demo remains independent of this selection. Preview cards are synthetic legal examples, visibly labeled as demos, and never enter live settlement state.
