# Research

- Decision: same-hand `mergeSnapshot` transition, after `syncStickyWinnerReveal`; observe next hand in `onSnapshot` before existing defer. Rationale: disposable passenger in existing reveal; changing WINNER_REVEAL_MS or scheduling gameplay is prohibited.
- Decision: royal from `mapRevealedShowdownCards` plus board through existing evaluator; board-only royal is provable too. Rationale: never inspect hidden opponent cards; category alone cannot distinguish royal from other straight flushes.
- V2 decision: sum per-recipient `presentation.pots[].recipients` for contested main/side pots. V3 keeps those exact recipient sums while trusting the validated pot classification, which also admits an awarded all-folded main pot with one eligible player; `return` pots remain excluded. Split recipients are checked individually. Missing buy-in skips the pot effect.
- V3 decision: implement only a page-local streak from newly observed complete result transitions in the current uninterrupted connection. Existing ordered transitions plus exact hand IDs and reset-on-reconnect are sufficient without recovering history. If a hand is missed, incomplete or out of order, discard counts. No history/WS/backend fields are added.
- Decision: layered CSS with existing locally hosted chip art; no new raster assets. Rationale: small payload and bounded mobile work, no dependency/download overhead.
- V3 decision: a verified effect starts on its newly observed settled transition even when the Winner window has little time remaining. Run a 1600 ms hero and 400 ms ring-only exit; ordinary transitions dim but do not cancel it. The overall two-second bound is independent of gameplay timing.
- CI root cause: the actual failure was `tests/e2e-ui.spec.ts` timing out at `page.goto(file://.../game_cats.html)` while waiting for the full `load` event; 65/66 Playwright tests passed and Chromium launched. The missing `libgraphene`/GTK warning came from the later generic `playwright install` downloading unused WebKit after CI had installed Chromium with dependencies. Bound navigation to DOM readiness and scope browser preparation to the selected browser.
- V4 decision: reuse `positionCelebration()` and its existing render/layout/scroll callers to re-resolve the winner's stable `userId + seatNo`, including the ring-only tail. Identity replacement remains immediate teardown; measurement or safe-placement failure fades only the overlay and schedules cleanup no later than the existing expiration. No polling or replacement target is permitted.
- V4 decision: the preview's compact target is an explicit transient selection from current visible nonlocal seats. Rebuild visible options but preserve only the same still-valid `userId`; activation resolves that exact identity again. A stale/missing target is a no-op with guidance, never a fallback.
