## Supported key contract

Existing `xp-ledger.mjs::createXpLedgerKeys()` owns private generators. Authenticated prefix is `kcswh:<env>:xp:v3:user:<UUID>:`; explicit anonymous prefix is `...:anon:<SHA256(anonId)>:` (anonymous IDs can also be UUIDs). Suffixes: total, daily:date, session:hash(sid), sync:hash(sid), state:hash(sid), server-session:hash(sid), lock:hash(sid), registry:hash(sid), profile, hidden, ratelimit:minute, conversion:hash(anonId), conversion-once. No plaintext session capability or email in keys. Shared boards/IP counters remain outside private space. Existing Warsaw XP day/week periods are preserved; bonus UTC rules are unchanged.

Every guarded raw/Lua writer registers private keys/shared boards in owner `keys` sorted set in the same fenced Lua execution, including direct profile/session/admin/visibility writes and conversion. The index is account-lifetime metadata; conservative references to expired/deleted keys are safe and retained until owner cleanup. Session/sync/state/server-session TTL is finite (60s–7d), lock TTL existing 5s, rate counters 60s, pair conversion marker 7d; account conversion-once remains until deletion. Session IP rate-limit increment/expiry and administrative day/week score/expiry are atomic Lua effects, including unchanged-score refreshes. Daily counters expire with the existing 14-day board horizon; lifetime/XP profile/hidden flags remain attributable until deletion. There is no legacy dual-read.

Cleanup reads only this owner index in batches ≤100, validates every member before mutations, deletes private keys and removes exact UUID members from shared boards. Final empty index + BLOCKED + expected epoch are checked within Lua. Corrupt foreign references deny, preserving other owners. Missing epoch or cutover proof cannot produce done:true. Lost response/restart retries are idempotent. Legacy runtime cleanup returns incomplete without scanning. Recovery must reconcile tombstones before installing a new epoch after loss/restore.

The existing default-false SQL release row gains a private `redis_cutover` JSON attestation, not another table: namespace, SHA256(exact REST URL), fresh epoch, reviewed manifest_hash, writers_drained=true, legacy_xp_reset_verified=true. No approval is seeded. The endpoint fingerprint and epoch bind it to the actual target; operator attestation requires evidence below, not merely setting booleans. Schema proposal is local only.
